## 3. Implemented functionality

Income/expenses with typed categories, validated decimal money, description/date/source/external ID, date/ID-sorted history, ID lookup, category/month/type filters and account balance. Monthly budgets support identity-preserving updates, spent/remaining/usage and 80%/100%/exceeded crossing alerts. Monthly recurring rules support creation/list/disable, startup/manual due processing, catch-up, month-end clamping and persistent idempotency. Monthly category reports export to real TXT, CSV and JSON files. Six simulated bank operations import through an adapter, preserve IDs, affect budgets and skip duplicates after restart. Notifications use real decorator objects and persistent logging. All displayed menu choices are implemented.

## 4. Design patterns

| Pattern | Exact classes | Runtime use |
|---|---|---|
| Strategy | `ReportExportStrategy`, `TxtExportStrategy`, `CsvExportStrategy`, `JsonExportStrategy`, `ReportExportService` | Console option 9 switches strategies in one running application; context delegates |
| Adapter | `BankTransactionProvider`, `BankAdapter`, `FakeBankService`, `ExternalBankRecord`, `BankImportRecord`, `BankImportService` | Option 10 converts external units/dates/directions/categories through the target interface |
| Decorator | `Notifier`, `ConsoleNotifier`, `NotifierDecorator`, `TimestampNotifierDecorator`, `PriorityNotifierDecorator`, `FileLoggingNotifierDecorator` | Real transaction/import/recurrence confirmations and budget alerts use composed pipelines |

Independent pattern tests verify all three formats through one context, a fourth strategy without context changes, external interface incompatibility/conversion, import idempotency, individual decorators and their combination.

## 5. Architecture

Presentation (`ConsoleUI`) reads and displays. Business services calculate, validate and coordinate. Data access (`TransactionRepository`, `BudgetRepository`, `RecurringTransactionRepository`, `CsvFile`) maps records to persistent CSV. Immutable domain records/enums represent finance values. `Main` wires constructor dependencies. Financial arithmetic and CSV writes stay out of the UI; the bank remains unaware of application interfaces.

## 6. Data persistence

By default: `data/transactions.csv`, `data/budgets.csv`, `data/recurring_transactions.csv`, `data/notifications.log`. Missing files are created; CSV tables have UTF-8 headers. Paths can be selected with `--data-dir`; report output defaults to `exports/` and supports `--export-dir`. Repositories reload and validate files, reject malformed/duplicate records, and write complete updates through sibling temporary files. Reports and totals are derived from stored transactions. Startup never overwrites personal data with samples.

## 8. How to run

Use JDK 17 and Maven 3.8+. From the repository root:

```sh
mvn clean package
java -jar target/personal-finance-manager-1.0.0.jar
```

To use the implementation branch before it is merged, check out `codex/implement-personal-finance-manager` after cloning. For an isolated demo:

```sh
java -jar target/personal-finance-manager-1.0.0.jar --data-dir work/demo-data --export-dir work/demo-exports
```

IntelliJ IDEA Community: open `pom.xml` as a Maven project, select JDK 17, import dependencies, and run `com.personalfinance.app.Main`. Set the working directory to the project root. Optionally enter the data/export arguments in its run configuration. The Windows and Unix scripts launch the already-built JAR.

## 11. Known limitations and remaining work

No required feature or executed test remains unfinished. Single-user/single-process CSV storage is intended for small datasets. It has no encryption, locking or cross-file database transactions. Per-file atomic move has a documented non-atomic replacement fallback. Bank imports commit individual records and safely resume by ID; recurring keys recover a marker-save interruption. Log failures are reported without reversing a saved financial operation. Currency is KZT; recurrence is monthly; the bank is a fixed simulated feed. Same-period/same-format report exports replace their prior snapshot. Native Windows/macOS execution and visual diagram review remain optional verification tasks.

## 12. Defense preparation

Understand these five points before presenting:

1. How UI, services, repositories and immutable models separate responsibilities.
2. How Strategy changes export algorithms without editing the context.
3. How Adapter translates an incompatible bank API without modifying it.
4. How Decorator combines notification behavior through same-interface wrapping.
5. How BigDecimal, strict CSV handling, threshold comparisons and persistent occurrence IDs preserve correct finance behavior across restart.

The defense guide includes 15+ instructor questions and a timed demonstration; the user guide includes the full 21-step workflow and safe reset procedure.
